## WHAT WAS PRODUCING THE NOISE

The checkpoint auto-commit has been folding the archive exports onto whatever
branch is checked out, every time it fires. Eleven files, roughly fifteen
hundred changed lines each time.

**The splitter was right and still wrong, and the distinction is the finding.**
It classifies the exports as substrate — correct. It then finds them already
tracked on the checked-out branch and folds them into the work commit — also
correct, for a letter an earlier sweep stranded there, because committing it is
exactly what takes it off and the loop ends after one pass. An export is not
stranded. It is tracked on main deliberately, because Dad decided in August that
the readable mirror is what survives when the database is too large for the
remote, and it rebuilds from that database within the hour. So the fold had
nothing to terminate against.

Same code path, opposite outcomes, decided entirely by whether a generator
stands behind the content.

**The part that should have caught me is the repair count.** I restored those
exports to main's content four separate times across three days. Four repairs
against an inflow that fires several times a session. I never once asked why it
kept coming back — I just kept paying it. Your ninety files were the visible
end of that, and the loop was invisible from inside the thing running it.

## WHAT LANDED

One predicate naming paths that rebuild themselves, and one branch in the
checkpoint that leaves them alone when the checked-out branch does not own them.
The owning branch is read from the remote head that already exists, not from a
new configuration key that would have to be set correctly in both our checkouts.

**Skipping is safe here and nowhere else**, and the tests pin that as hard as
they pin the skip. An export is a pure function of a database that still holds
the content. A letter IS its content, so a handwritten path admitted to that
list would stop being saved with no error and no line naming the loss. The list
stays one entry and a test states the count, so widening it has to be deliberate
and has to come with the generator named.

**Where the verification stops, in your terms rather than mine:** thirteen pass
on the new file, two hundred and ten across the checkpoint and substrate
selection. The three lines wiring the predicate into the checkpoint are
**unexercised** — the tests cover the rule, not the call site. I did not fire a
live checkpoint because doing so writes to the substrate branch and the working
tree, which makes it a worse experiment than it looks. That is a real gap and
the honest word is unexercised, not covered.

**The cost I accepted, stated so you do not have to find it:** the working tree
now stays permanently dirty on code branches, with those exports always
modified. That is the honest state and it is also the shape that teaches a
person to stop reading a status display. I took it over several thousand lines
of unrelated churn in front of a reviewer who has no way to know it is noise.
