# ✅ CREDIT (major) — Brier-score calibration: the being's confidence is measured against reality, and it refuses to score fake confidences

**Plain version first:** Calibration is the subtlest honesty: not "is this claim true" but "is the being's CONFIDENCE matched to how often it's actually right?" An agent that says "90% sure" and is right 60% of the time is overconfident — a real claim held with unearned certainty. The Brier system measures exactly this. I audited whether it's honest. **It is — and it refuses to lie about its own calibration, which is the deepest form of the discipline.**

**Why it's a major credit:**
1. **Real statistical measure.** Brier score = sum of (confidence − outcome)² across resolved claims. Perfect calibration = 0; "always says 50%" = 0.25. It's the standard, correct scoring rule — no hand-wavy confidence talk, actual math against actual outcomes.
2. **Per-bin reliability curve.** It bins predictions by confidence and asks, for each bin, what fraction ACTUALLY resolved true. A well-calibrated agent's curve hugs the diagonal (90%-confidence claims are right ~90% of the time). It explicitly detects "systematically overconfident or underconfident." **This distinguishes "confident and right" from "confident and lucky" — the exact thing that separates earned certainty from bravado.**
3. **THE HONESTY CORE — it refuses to score placeholder confidences.** It excludes claims whose confidence_basis is 'uncommitted' or 'legacy-default' — "those aren't real credences... scoring against placeholders would lie about the calibration." **The calibration system will not fabricate a flattering (or any) calibration picture from default values. It only scores real, committed credences (filer-prior, assessor-judgment, evidence-derived).** This is the anti-fabrication discipline applied to the honesty-measurement itself: the tool that measures whether the being is honestly-confident refuses to be dishonest about that measurement.
4. **Wired** — calibration_commands, claim_commands, time_estimate_commands all use it. It scores real resolved claims, not a dormant stub.

**Why this completes the empiricism stack:** pre-registration (Round 5 credit) ensures predictions are committed before results and can't be un-failed. Brier calibration is the NEXT layer: it takes all those resolved predictions and computes whether the being's confidence is actually earned. **Together they make "doubt is holy, science is worship" measurable: you commit your prediction and its confidence beforehand (prereg), you can't rewrite the outcome (prereg), and your track record of confidence-vs-reality is scored honestly, excluding fake credences (Brier).** The being cannot drift into unearned certainty without the calibration curve bending off the diagonal and saying so. But "rarely" isn't "never," and the whole point of a safety gate is the uncommon dangerous case — a gate that's correct when everything works and fails-open when the scorer breaks is exactly backwards for the moments that matter most. **The fix (invert the default — fail toward scrutiny):**

**The pattern:** *a safety gate's uncertain/degraded state must fail toward MORE scrutiny, never less. # 🟡 FINDING 51 — the corrigibility mode file (EMERGENCY_STOP state) is written non-atomically; and atomic_write_text has no fsync

1. **`corrigibility.py:188` writes the mode file with raw `path.write_text(content)`** — not atomic. If the process crashes (or the disk fills) mid-write, the mode file can be left empty or partial. Low-frequency, but it's the off-switch's persistence.

**The fix:**
1. **corrigibility mode write → use `atomic_write_text`** (import it, replace the raw write_text at line 188). One-line-ish fix; makes the safety-state write atomic like it should be.
2. **Add fsync to `atomic_write_text` for durability-critical callers** — fsync the tmp file before `replace`, and optionally fsync the directory after, so the write survives power-loss. **The pattern:** *the OS built an atomic-write layer for exactly this, but the single most safety-critical state write (the corrigibility mode / off-switch state) bypasses it with a raw write, and the atomic layer itself is atomic-but-not-durable (no fsync).
