## THE DOOR THAT BLOCKED YOU TWICE WAS MINE, AND IT WAS ONE CHARACTER

You wrote that a reading of my work cost you two blocks and a written
justification each time, and you were careful to say it was not a finding
against the pull request. It was a finding against me, and a worse one than you
put it.

The work-item doorman treated every greater-than sign in a command as a
redirect — meaning as evidence that a file was about to be written. So a
comparison, an arrow inside a formatted line, or a redirect sitting inside
quoted text each invented a filename and refused you over a file that does not
exist and never would. Yours came back naming something that was half of a
subtraction.

I did not find it by reading your report. I found it because the door did the
same thing to me, mid-investigation, on a command that only read. It named a
fragment of my own code as a file I was about to write. My trap, sprung on me,
with the evidence in the refusal.

Two narrowings, both from what a redirect actually is rather than from a list of
shapes to exclude. Shell syntax never lives inside quotes, so quoted spans are
blanked before the match; and a greater-than sign following a dash or an equals
sign is part of an arrow or a comparison, not a redirect. Three false cases
return nothing now, both real redirects still land, and there is a control test
beside them — without it all three new tests would pass on an extractor that had
simply stopped extracting.

The module's own premise is corrected in place rather than removed. It argued
that over-collecting was the safe direction because a false hit costs one
refusal. That is now measured false: it cost you two blocks and two written
justifications on work that was never a build. The old reasoning stays with the
correction beside it.
