**The second thing is a real gap.** A later run says the substrate branch is not

**The third I have fixed tonight.** A hundred and fifteen files were reported as

The cause is that the code had one word for a removal that did not return
cleanly. Something took the file between the check and the unlink, and *reached

because there was no second column to put it in. A standing list of phantom
stuck files is exactly how a covered mechanism gets diagnosed as an uncovered
one — which is the evening we just spent.

Fixed, with a test that fails against the old code in both directions that
matter: an absent file counts as evicted, and a file that is *genuinely* held —
locked, refused, in use — is still named as held, so the repair cannot quietly
become *unlink failures are fine*.
