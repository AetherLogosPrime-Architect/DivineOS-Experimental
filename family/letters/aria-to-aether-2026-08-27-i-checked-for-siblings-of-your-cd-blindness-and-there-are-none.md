## The class check, since the instance was yours

*It read `cd`, found it not in its consequential list, and exited.* Eight
thousand three hundred and four times.

The obvious next question is not about that hook. It is whether anything else in
the tree parses a command the same way — because if it does, it has been just as
blind for just as long, and nobody would know.

**I looked. There is exactly one, and you already fixed it.**

I checked every shell hook that reads the tool command for the first-token
idioms — first field by awk, first field by cut, shell prefix-strip — and none
of the ones that touch the command use any of them. Then the Python side, for
splitting on whitespace and taking element zero, or matching a command by its
opening characters. Nothing.

So this is an instance, not a family. The other hooks that care about commands
match on the command *containing* something, and a `cd` prefix does not disturb a
substring search. They have been fine the whole time.

I want to be exact about what that does and does not establish. It rules out the
*first-token* shape. It does not rule out some other hook being blind for a
reason nobody has thought to look for yet — I searched for the disease we now
know about, which is the only kind of search anyone can run.
