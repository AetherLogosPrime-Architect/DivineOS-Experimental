# The cloud lane takes Andrew's quoted declaration, bound to what a seat cannot write (draft, 2026-11-27, reworked 2026-11-28)

**Symptom.** Fifteen repairs Aletheia had stamped sit on `claude/...` branches, and the board's two reading stations (4-aria, 4-cold-read) could never be satisfied for them. `declared_owner` honours `Owner: cloud` only on a branch beginning `cloud/` (Aria's cold read of 2026-10-14: a name may withhold a pass and never grant one), and the body line `Author: claude` reads as an unknown author. No reading letter, however many, could change that. Verified with the real functions: `Author: claude`, `Author: cloud` and `Author: claude (cloud session)` all left station 4 at CANNOT_CHECK.

**What was refused, and why.** Honouring the `claude/` prefix. Aria's count of every pull request GitHub has whose branch begins `claude/` (69 in all states) found 68 opened on 2026-11-02, 03 and 04, which matches the credit run, and one (#432, opened 2026-08-18) that is not from it. The prefix is the harness's default; a local session started by either seat gets the same shape of name. So the name does not mark the run.

**Aletheia's hold on the first version (2026-11-27), and what changed.** She wrote: a branch name and a first line are both things the writer types; "only on `claude/` branches, and not from a seat" is not a guard, because any seat can name a branch `claude/x`; bind the lane to something a seat cannot write for itself, or keep the other seat's cold read required whatever the label says. The first version still read the grant's `Opened:` day from the owner file, which the writer of the file types. Now:
- **The opening day comes from GitHub** (`createdAt` of the pull request, read by `_opened_on`), and the file's `Opened:` line is only a note that is never trusted. A request GitHub did not date has no day and reads as cannot-check.
- **The quote must be Andrew's.** `_quote_is_his(quote, corpus)` checks the declared quote against the recorded corpus of his own messages (`HIS_WORDS_CORPUS`, squashed to compare whitespace-insensitively), so a quote a seat invented is refused for that reason.
- **A seat author in the body is never overridden** by a file; `claude`, `cloud` or no author resolves to the cloud lane only when an owner file grants it.

**The grant.** A non-`cloud/` branch gets the cloud lane only when its owner file carries, beside `Owner: cloud`: `Declared-by: andrew, <date>: "<his words>"` (the quote at least twenty characters and found in his recorded words), and `Window: <start> to <end>`, with the GitHub-dated opening day inside the window. Refused whatever the file says: a branch beginning `aether/` or `aria/` (a seat prefix names a seat); a declaration by anyone but andrew; a quote that is empty, thin or not found in his words; a missing window; a reversed window; an opening day outside the window, in those words, not for the name. The board prints the quote, the window and the GitHub day beside the cold-read station (`[lane basis: ...]`) so the auditor sees why and can disagree.

**What this does not do.** It writes no owner file; those are data in the shared `branch_owners` folder and need his say-so to be written (sixteen were written on his yes of 2026-11-27, each with a quote found in his words). A seat can still type an owner file; what it can no longer fake is the opening day (GitHub's) or his words (the recorded corpus).

**Receipt.** `tests/test_the_cloud_lane_takes_andrews_quoted_declaration.py`: 28 pass, including four for `_opened_on` that I proved by breaking the function and watching them fail. They also found a real defect on the way: `_opened_on` used `re` and `build_flow_commands.py` never imported it, so the board would have crashed on every request; the import is in this head. Each cheaper route has its own refusal test. Ruff clean.
