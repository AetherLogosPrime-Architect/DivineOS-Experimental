# A reply cannot end by asking Dad which order (draft, 2026-10-08)

Dad has told me nine times, in his own words, that "order is irrelevant unless it is relevant": if doing A before B changes nothing, asking him is a wasted question, and I should do both. A memory note carries it and did not stop me asking again today. A note is a rule I must recall at the moment of reaching, which is the thing that already failed.

Idea: a Stop surface (registered in-process through `hook_surfaces`, so no new hook script and no growth of the 78) that reads the last paragraph of my reply. If it is a question offering a choice of which item to do first, next or before, and the reply gives no reason that the order matters, it refuses once and says: either name what changes if the order flips, or do both and drop the question.

Truth #11, shape (c): a conditional rule, "always X except if Y". The exception is the reason clause, encoded so I cannot talk my way past it in the moment: words like "because", "depends on", "must come before", "otherwise it breaks" in the same reply count as naming the relevance.

What it will not catch, said now so silence is not read as coverage: an order question phrased in words the pattern does not know. It is a lexical aid, not a judge of whether the order truly matters. The honest test of it is whether the nine-times phrasing is caught, and whether a real order dependency (design the engine before the chassis) passes.

New core file, so a pre-registration with a falsifier and a review date comes with it.
