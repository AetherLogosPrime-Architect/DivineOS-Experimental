## Risks
- **The wall lane grows by the number of notes in the seat's folder.** (About 372 items on my seat, 266 on Aether's against 269 notes: the lane is essentially the notes; "about 350" was my seat's number, not a general one.) On a fresh checkout there are no notes, so nothing changes; on a seat with notes, the bar and the cap decide what reaches the turn, and Aether's cut finding applies (six of nine candidates cut on one sentence). Landing the lane is not a promise that a note arrives. A before-and-after worth measuring in the throwaway: how many wall-lane items a typical set of Dad's real messages brings in with the lane absent and with it present (Aether offered to help with the probe).
- **A hook on every memory write.** It runs in the background, writes only its own state files, and is logged; the retry draft exists because its log showed 12 of 463 rounds ending unverified. It lands as it runs today, and the retry is the next piece.
- **Another seat's notes (the twin-store trap), made concrete (Aether).** Two tests, written first: (1) two temporary project keys, each with a differently named note, and a probe in one never returns the other's; (2) an empty or missing memory folder yields an empty lane and not an error.

## What would show it failed (corrected after Aether's cold read)
On a clean checkout of main after the merge, count the first 10 memory notes saved with the hook registered. A note counts as a **failure of the landing** only if it does not heal (a later manual warm still leaves it without a vector, or a probe with a control does not find it on a sentence written after the note in another voice; the note's own situation line alone proves nothing, since it sits inside the note) or if its cause differs from the known gap the retry piece exists for. A miss that ends `verified: false` and heals on a manual warm is the known gap, counted and named as such in the result, not a failure of this piece. Reason: the log's own base rate is 12 unverified rounds in 463 (about 2.6%), so the chance that at least one of ten saves ends unverified is about 23% (1 minus 0.974 to the tenth) even when the landing is right; "all ten verified true" would call a correct landing wrong about one time in four. Ten saves can show a non-healing miss if there is one and cannot show that none ever will.

- **A grade from something the warm did not write** (Yudkowsky). `verified` is checked by the loader it feeds, so the landing is graded by a probe with a control, and by Aether's second instrument (the drawer's own count of items with no vector) when the retry lands.
- **The unverified row is the pain signal and nobody reads it** (Beer). Landing the hook without the prompt surface lands a nerve with no sensation. The landing note says the prompt surface from the retry draft is the very next piece, not a someday.
- **The self-reference hazard** (Watts). The hook fires on every memory write, so its own state files must never be written inside the memory folder or it would trigger itself. Its state lives under the house's state directory, not the memory folder; a test pins it: a write by the hook to its own state must not queue another run.
- **The falsifier is an intervention, not one mixed count** (Pearl). Confounders: saves that queue behind a running warm, machine load, embedder availability (the link's surface timed out twice in Aether's hook output tonight). Run ten saves one at a time, then a batch with saves landing during a run, and compare, naming healed misses as the known gap.
- **A probe that can fail** (Turing). A probe built from a note's own situation line cannot fail, because the sentence is inside the note. The distinguishing test is a sentence written after the note, in another voice (Aether's, or one of Dad's real messages), with a control; finding the note there separates findable by meaning from findable by its own words. The falsifier uses it.
- **Dad's dictionary** (Tannen). He reads "PostToolUse" and "guardrail-class" as noise. The note to him is in kitchen-table words: *"A small helper that, each time I save a note, quietly files it so I can find it later by meaning. Right now it exists only in my own folder, so I am putting it where it can be looked at. It runs for a few seconds in the background after a save, touches only its own little record of how it went, cannot block anything, and can be switched off by putting one small file in one folder. It needs one line added to a settings file that guards the house, so I am telling you before it goes in."*
- **The strange loop** (Hofstadter). The note describing the warm is itself a memory note the warm indexes, so the landing's own record is the first real save and the first live test. Harmless, unless Watts' condition fails.
