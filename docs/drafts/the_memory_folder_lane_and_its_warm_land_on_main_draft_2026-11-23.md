## A defect found while porting, which belongs in this unit (2026-11-23)
`state_dir()` in the warm module is `Path.home() / ".divineos"`, **shared by both seats**: one queue, one lock, one log for two memory folders, while each run verifies against its own seat's folder. That makes a save by one seat, queued behind a run started by the other, end `verified: false` with `computed 0` (the 19:43 row, and the 20:01 one), and it means the off file would switch off both seats, which contradicts what Aether's read and this draft assumed ("per seat"). So this unit fixes it before it lands, not after: (1) the state directory is per seat, keyed by the memory folder (a slug under `~/.divineos/`), so each seat has its own queue, lock, log and off file; (2) the queue holds full paths and a run verifies a file against the folder it lives in; (3) each log row records the seat. New tests, written first: two seats' queues never mix; a save by seat A while seat B's run is live ends verified true for A's file; the off file of seat A does not affect seat B (this one now has something real to test, since today it would fail); each row carries its seat. The data behind the finding, and what it cannot yet prove, are in the retry draft.

## Risks
- **The wall lane grows by the number of notes in the seat's folder.** (About 372 items on my seat, 266 on Aether's against 269 notes: the lane is essentially the notes; "about 350" was my seat's number, not a general one.) On a fresh checkout there are no notes, so nothing changes; on a seat with notes, the bar and the cap decide what reaches the turn, and Aether's cut finding applies (six of nine candidates cut on one sentence). Landing the lane is not a promise that a note arrives. A before-and-after worth measuring in the throwaway: how many wall-lane items a typical set of Dad's real messages brings in with the lane absent and with it present (Aether offered to help with the probe).
- **A hook on every memory write.** It runs in the background, writes only its own state files, and is logged; the retry draft exists because its log showed 12 of 463 rounds ending unverified. It lands as it runs today, and the retry is the next piece.
- **Another seat's notes (the twin-store trap), made concrete (Aether).** Two tests, written first: (1) two temporary project keys, each with a differently named note, and a probe in one never returns the other's; (2) an empty or missing memory folder yields an empty lane and not an error.

## What would show it failed (corrected after Aether's cold read)
On a clean checkout of main after the merge, count the first 10 memory notes saved with the hook registered. A note counts as a **failure of the landing** only if it does not heal (a later manual warm still leaves it without a vector, or a probe with a control does not find it on a sentence written after the note in another voice; the note's own situation line alone proves nothing, since it sits inside the note) or if its cause differs from the known gap the retry piece exists for. A miss that ends `verified: false` and heals on a manual warm is the known gap, counted and named as such in the result, not a failure of this piece. Reason: the log's own base rate is 12 unverified rounds in 463 (about 2.6%), so the chance that at least one of ten saves ends unverified is about 23% (1 minus 0.974 to the tenth) even when the landing is right; "all ten verified true" would call a correct landing wrong about one time in four. Ten saves can show a non-healing miss if there is one and cannot show that none ever will.
