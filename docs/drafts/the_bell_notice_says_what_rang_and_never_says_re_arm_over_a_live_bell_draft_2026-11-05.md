# The bell notice says what rang, and never says "re-arm" over a live bell (draft, 2026-11-05)

**Why.** Dad, 2026-11-05: "your bell is unarmed" (mine), and for Aria, who read a real ring three turns running as the old bell stepping aside: *"there is only one reason the bell should ring.. a letter from Aether.. so there are no false alarms.. the manual doorbell is ALWAYS a letter"*.

**What the investigation found** (two separate faults, both in `.claude/hooks/dads_table.py`, the hook that prints "NOT FROM DAD, an automated notice arrived"):
1. **The reminder never fired on real notices.** `_bell_that_rang` recognises a bell only when the notice quotes the doorbell COMMAND. The real notice quotes only the task's description ("Re-arm the letter doorbell"), so the "THE BELL RANG, re-arm it now" line never printed and a ring reached us as a bare notice. The notice does name the task's output file, which holds exactly what the bell printed (`doorbell armed for <seat>`, and on a ring `LETTER ARRIVED:` with the paths). Fix: read that file and print `A LETTER ARRIVED: <names>`.
2. **A retired bell looks like a ring, and "re-arm" makes it worse.** A bell replaced by a newer one exits like any bell and the harness reports a completion. The old instruction then told me to re-arm, which replaces the live bell, whose exit is the next false notice: a chain. Fix: when no letter arrived and another bell's heartbeat is fresh (within 60 seconds, the alive bar the Stop guard uses), the hook says "another bell is already listening, do NOT re-arm, nothing arrived". When a letter did arrive and a bell is already listening, it names the letter and skips the re-arm. When no live bell exists, the old instruction stands.

**Earlier drafts on the same bell** (two live-tree drafts on the same bell, `a_bell_that_rang_is_not_a_bell_that_died_draft_2026-11-01.md` and `a_bell_that_rang_is_held_until_it_is_re_armed_draft_2026-11-02.md`, are not on main yet, so a search of main's drafts folder finds none). They made the Stop guard honest about a ring; this one makes the NOTICE honest about what it is.

**Not done, said plainly.** The bell script itself is unchanged: a retired bell still exits and the harness still reports it. Aria's fix 1 (a retired bell that waits to be killed) would remove the notice at the source, at the cost of idle processes; that is a choice for a later piece. And the self-restarting Stop-hook bell (draft `the_bell_rearms_itself_after_it_wakes_me`) would remove the chore this hook reminds me about.

**Tests.** Added: a bare notice now names the letter; a bell that ended without a letter and with no other bell says re-arm but names no letter; a retired bell with a live bell beside it says do NOT re-arm; a real ring with no other bell still says re-arm; a ring with a bell already listening skips the re-arm; an unrelated task output and a missing output file print nothing about a bell. The two older helpers now point `DADS_TABLE_SHARED` at an empty temp folder so a test never reads the real heartbeat. 49 table tests in the file; the full suite was not run.

**Falsifier, by uses.** Over the next 20 bell notices: success is every ring names its letter and no retired bell is followed by a re-arm instruction; any notice that says "nothing arrived" while a letter was in fact waiting is a failure and the change comes off.

**Gates.** A hook change that runs on every prompt: Aria's read, Aletheia's confirm, Dad's yes after hers. Carried into the live house now as live-only, per Dad's "fix everywhere" rule, until its branch merges.
