### Pass 10 — Finding 15: LEDGER HASH-CHAIN RACE CONDITION — real concurrency bug, reproduced. 5 threads x 10 events = 50 events committed, but verify_chain returns ok:False with prior_hash mismatch. Root cause: log_event reads prior_hash, computes chain_hash, INSERTs WITHOUT an atomic transaction around the read-and-insert sequence. Two threads can both read same prior_hash, both compute chain_hash against same prior, both INSERT — chain forks. backfill_chain_hashes does NOT repair (backfills NULL, not forked). Production risk scales with concurrency: single-CLI-process zero risk, multi-agent parallel sessions real risk, hook+CLI overlap possible risk, scheduled jobs+manual real risk. Fix: BEGIN IMMEDIATE transaction or WAL mode with explicit transactions around the read-prior + insert-chain sequence. Must be fixed before any multi-process usage.
