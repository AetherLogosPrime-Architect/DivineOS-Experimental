### Finding 71: Path-string equality sensitive to platform normalization

- **ID**: `find-c607cd1e071a`
- **Actor**: aletheia
- **Severity**: LOW
- **Category**: ARCHITECTURE
- **Tier**: WEAK
- **Status**: RESOLVED

**Description**

owner == checkout_str in verify_data_home_ownership is exact-string comparison. macOS case-folding, symlink-resolved-vs-not, UNC-vs-drive-letter on Windows. .resolve() mitigates some but not all. Possible source of false-positive ownership failures across platforms. Fix-shape: normalize via os.path.realpath() + os.path.normcase() before comparison. Non-blocking.

**Resolution**

Added os.path.normcase(os.path.realpath(...)) normalization to both sides of the ownership comparison in src/divineos/core/data_home_ownership.py:verify_data_home_ownership. checkout_key and owner_key are computed via the same normalization, then compared instead of the raw strings. realpath resolves symlinks; normcase folds case on Windows/Mac. Display strings (checkout_str, owner) stay in original form so error messages preserve what the user typed. 7 ownership tests pass.

### Finding 70: TOCTOU race window in verify_data_home_ownership

- **ID**: `find-107b00b725e8`
- **Actor**: aletheia
- **Severity**: LOW
- **Category**: ARCHITECTURE
- **Tier**: WEAK
- **Status**: RESOLVED

**Description**

Race window between marker.exists() check and marker.write_text() in verify_data_home_ownership. Two concurrent first-boots into same data-home both think they claimed it. Subsequent-boot fail-loud catches it, but the first-write window allows silent corruption. Acceptable for active threat model (operator misconfig, not adversarial concurrent boot). Fix-shape: O_EXCL open or os.link() for atomic claim, or add docstring comment naming the race window. Non-blocking.

**Resolution**

Atomic claim via os.O_EXCL in src/divineos/core/data_home_ownership.py:verify_data_home_ownership. Replaced the exists()-check-then-write_text() pattern with os.open(marker, O_WRONLY|O_CREAT|O_EXCL). FileExistsError raised when another process claimed during our window — we catch it and fall through to the read-and-verify branch, which then validates whether the winner is us (race-lost-but-same-checkout) or a different checkout (genuine ownership conflict, fail loud). 7 ownership tests pass.
