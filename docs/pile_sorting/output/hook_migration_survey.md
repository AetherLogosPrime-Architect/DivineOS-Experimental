# Hook migration survey: the shell scripts that still hold their own logic

*Round four, job B. 2026-10-08, cloud helper. Read-only: no migration is written here, and nothing under `.claude/` or `src/` was touched.*

A picture: a building where thirty-five of the doors each keep their own little brain in the door frame, when the house wants one brain in the middle and every door just pointing at it. This sheet is the tour: what each door-frame brain decides, where in the middle brain it could live, and how you would know the move changed nothing.

## The count differs from the plan, and why

On `origin/main` (`cc4714dc`), `divineos hook-layer show` reports **45** scripts that never call the OS, 5,862 lines, not 35 and about 5,200. The plan's number is right once ten scripts are taken out: those ten already call OS logic by module (`python -m divineos...`), which the measure's pattern (`from divineos`, `import divineos`, `divineos <word>`) does not see. Taking them out leaves exactly 35 scripts and 5,210 lines, which matches the plan. So the hook-layer measure over-counts by those ten; that is itself a small finding for whoever owns `core/hook_layer.py`.

The ten already-thin scripts, with the module each already calls:

- `session-init-once.sh` (311 lines): calls `-m divineos.core.hook_context_merge, divineos.core.hook_context_merge`
- `andrew-past-writing-surface.sh` (63 lines): calls `-m divineos.core.andrew_past_writing_surface, divineos.core.andrew_past_writing_surface`
- `require-goal.sh` (47 lines): calls `-m divineos.hooks.pre_tool_use_gate`
- `his-state-is-his-to-say.sh` (43 lines): calls `-m divineos.hooks.his_state_claim_hook`
- `his-voice-ends-the-turn.sh` (42 lines): calls `-m divineos.hooks.his_voice_hook`
- `run-tests.sh` (35 lines): calls `-m divineos.hooks.targeted_tests`
- `session-checkpoint.sh` (34 lines): calls `-m divineos.hooks.post_tool_use_checkpoint`
- `shoggoth-gate.sh` (32 lines): calls `-m divineos.core.operating_loop.shoggoth_gate, divineos.core.operating_loop.shoggoth_gate.`
- `front-door.sh` (27 lines): calls `-m divineos.hooks.front_door_hook`
- `stop-distancing-intercept.sh` (18 lines): calls `-m divineos.hooks.distancing_intercept_hook`

## How each cell was found

One-sentence decisions come from each script's own leading comment, not from reading every body line by line; the harness event comes from `.claude/settings.json` and, for scripts that are children of the UserPromptSubmit table, from `dads_table_children.json`; the callers come from a text search over `.claude/hooks/`; the test column is a text search over `tests/` on main, split into tests that mention the script *and* use `subprocess`/`bash_executable` ("runs it") and tests that only mention it. Two tests, `test_gate_deny_messages_name_remedy.py` and `test_detector_wiring_contract.py`, mention nearly every hook because they scan all of them; they were not counted as exercising any one script. The "would become" and "surface" columns are proposals for Aether and Aria to decide.

## What the survey shows

- 13 of the 35 have a test that actually runs the script; 22 have none. Those without one are where a move is least protected, and for them the "before" live run in the last column has to be recorded first.
- Four of the 35 are not migration candidates as hooks: `_bail.sh` (a sourced library), `post-merge-doc-fix.sh` (a git hook, not a harness event), `post-push-verify-landing.sh` (superseded, unregistered), and `aletheia-boot-gate-preflight.sh` (kept registered as defence in depth behind the family-member seal).
- 18 of the 35 are not named in `settings.json` at all: they run as children of `session-init-once.sh` or the Dad's-table list, are sourced by other scripts, or are not wired. That means the registration count in `hook-layer show` understates how many scripts run each turn.

## What this survey could not do

- It did not read the bodies of the longer scripts line by line, so a decision hiding in a branch of `pipeline-exit-ambiguity.sh` (559 lines) may be missing from its one sentence.
- It did not run any script. The "before" live runs in the last column are described, not performed.
- The module and surface names are proposals; none was checked against names Aether or Aria may already have in a branch.
- Counts are from `origin/main` at the time of writing; the branch this file sits on is older.
